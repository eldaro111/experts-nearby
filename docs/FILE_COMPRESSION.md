# Хранение файлов проекта: nearby-pack-v1

Пользовательская инструкция и порядок установки: [UPDATE_FILE_COMPRESSION.md](../UPDATE_FILE_COMPRESSION.md).

## Поток данных

1. Браузер передаёт выбранные `File` в Web Worker; файлы читаются срезами по 1 МиБ.
2. Gear CDC разбивает содержимое на фрагменты: минимум 16 КиБ, условие границы по 16 младшим битам, максимум 256 КиБ. Фрагменты с одинаковым SHA-256 в пределах пакета хранятся один раз.
3. Zstandard, уровень 3, применяется к фрагменту, только если сокращает его минимум на 5%. Остальные фрагменты записываются без сжатия. Для отдельного файла весь контейнер должен дать минимум 5% экономии, иначе остаётся исходный файл.
4. Приложение резервирует загрузку через защищённый RPC, отправляет один объект в приватный `project-files`, затем финализирует запись. `file_size` — фактические сохранённые байты; `original_size` — сумма исходных байтов.
5. При скачивании RLS выдаёт временный подписанный URL. Worker проверяет SHA-256 всего объекта, границы контейнера, каждый восстановленный фрагмент и каждый файл. Отдельный файл возвращается без изменения байтов, папка — в виде обычного ZIP (Deflate). Подготовленный ZIP выдаётся только после завершения проверок.

`file_name` хранит исходное пользовательское имя. Новые ключи объектов Storage строятся из ASCII-символов для совместимости с ограничениями Supabase. Старые пути не изменяются. Привязка к проекту, имени автора, задаче и версии сохраняется.

## Контейнер

| Часть | Формат |
| --- | --- |
| Байты 0–7 | ASCII `NRPK0001` |
| Байты 8–11 | uint32 LE: размер JSON в байтах |
| JSON | UTF-8 манифест версии 1 |
| Payload | Последовательность уникальных фрагментов raw/zstd |

Манифест: `{version:1, kind:"single"|"folder", totalSize, files, objects}`.

`files`: `{path, size, sha256, chunks:number[], lastModified}`. `chunks` содержит индексы в `objects`; путь относительный, байты файлов не преобразуются.

`objects`: `{sha256, offset, size, stored, codec:"raw"|"zstd"}`. `offset` отсчитывается от начала payload, `size` — размер после распаковки, `stored` — сохранённый размер. Смещения последовательны, все объекты должны быть использованы. Хеш всего контейнера находится в `project_files.storage_sha256`.

Пределы: манифест 4 МиБ, 40 000 ссылок на фрагменты/объектов, 2000 файлов, 500 МиБ логических и сохранённых данных. Проверяются обход пути, абсолютные пути, конфликт файла и папки, коллизии регистра/Unicode NFC и недопустимые для Windows имена.

Перед вызовом WASM-декодера проверяются заголовок, объявленный размер и окно Zstd, чтобы исключить выделение памяти по произвольному размеру из недоверенного заголовка. Поддерживаются только создаваемые нашим кодом фреймы с известным размером и без словарей. SHA-256 проверяет целостность, а не право доступа: оно обеспечивается существующими RPC и RLS. SQL не читает и не проверяет байты Storage; заявленные клиентом логические размеры не являются доверенным учётом квот. Декодер независимо проверяет пределы.

## Совместимость и эксплуатация

- Отсутствующие метаданные и формат `raw` означают старый способ хранения. Новая миграция задаёт `raw` существующим строкам без переписывания содержимого.
- RPC `project_file_storage_version()` возвращает 1 при включённой функции; без миграции интерфейс оставляет только обычную загрузку. Значение 0 блокирует новые контейнеры и на уровне RPC; чтение существующих не отключается.
- `reserve_project_file_pack_secure` использует прежнюю проверку членства/пользователя/задачи/лимитов. Финализация дополнительно сверяет размер загруженного объекта. Метаданные формата после сохранения неизменяемы.
- Один объект относится к одной записи. Удаление использует прежний порядок: удалить объект Storage, затем запись через RPC. Межпроектного разделения блоков и сборщика общих блоков нет.
- Нужны Web Worker и WebAssembly. WASM берётся из зафиксированного `@bokuweb/zstd-wasm@0.0.27` и автоматически копируется в `public/vendor` командами `predev`/`prebuild`. Во время работы кодек загружается с того же сайта, без внешнего CDN. При ручном `next build` сначала выполните `node scripts/prepare-file-codecs.mjs`; предпочтительнее `npm run build`.
- Таймаут без событий Worker — 120 секунд. Отмена завершает Worker и чтение скачиваемого объекта. Крупные контейнеры и выходной Blob по-прежнему требуют памяти; это не решение для многогигабайтных сборок.
- Сжатие снижает передаваемые в Storage байты, но не заменяет резервное копирование, антивирусную проверку, возобновление передачи или защиту авторских прав.

## Проверки

`npm run test:storage` выполняет тесты формата на Node и проверки миграции/RLS в PGlite без удалённой базы. Дополнительный локальный CAD-набор можно передать переменной `CAD_TEST_ZIP`, указывающей на ZIP; без неё этот один тест пропускается. Пример PowerShell:

```powershell
$env:CAD_TEST_ZIP = "C:\полный-путь\assembly.zip"
npm run test:storage
Remove-Item Env:CAD_TEST_ZIP
```

Тест сравнивает каждый путь и каждый байт восстановленных файлов. Он не открывает инженерную модель в CAD-программе: это отдельная пользовательская проверка. В репозитории только синтетические данные тестов; предоставленная пользователем сборка не публикуется.

После `npm run build` команда `npm run test:storage:bundle` запускает именно собранный браузерный Worker с WASM в Node VM. Проверяет подключение кодека и восстановление папки с кириллицей. Глобальные объекты браузера эмулируются; тест не проверяет DOM, выбор папки, реальную сеть или поведение браузера при скачивании.
