## Что проверяет база

Уникальные и неизменяемые ER-коды; корректность имени; запрет самоподтверждённых языковых сертификатов; связность вуз/школа/группа; ограничения предложений справочника; маскирование скрытого профиля и цены; недоступность служебной последовательности; отсутствие прав публикации/выдачи роли редактора/очистки таблиц у обычного пользователя; приватность обращений, одно обращение адресату и суточный лимит; идемпотентное создание проекта из принятого обращения; настоящий статус приглашения; запрет отзывов до завершения и для постороннего; необходимость выполненных задач и участника; фиксация команды и задач; приватность университетских проектов; невозможность обхода PDF-квоты через браузерную запись; квота 15 МиБ; доступ к файлам по видимости; отсутствие черновиков и будущих публикаций в гостевой выдаче.

Минимальные схемы `auth` и `storage` в тесте — имитация платформенного окружения. Настоящие SQL-миграции и PostgreSQL RLS исполняются, но реальные HTTP API Supabase, JWT gateway, почта и объектное хранилище этим тестом не проверяются.

Для рекомендаций отдельно проверены: подбор и оповещения в обе стороны, нормализация тегов без смешения C/C++, объяснения и бонус общего вуза, исключение собственных/закрытых/завершённых/просроченных проектов и существующих откликов, маскирование скрытого профиля и цены, отсутствие снимков персональных данных в старых уведомлениях, запрет доступа посторонним и вызова внутренних функций, обе настройки отключения, независимое скрытие и восстановление, отсутствие дублей, общий лимит три оповещения за 24 часа даже для пользователя в обеих ролях, невозможность сбросить квоту изменением inbox или удалением проекта, отложенная доставка при следующем обновлении, начальное заполнение, ограничение частоты пересчёта и отсутствие лишнего оповещения при приглашении в той же транзакции. Конкурентная нагрузка в реальном PostgreSQL отдельно не моделировалась.

## Что проверяет браузер

Главная, вход, вузы, эксперты, новости и правовые страницы; отсутствие горизонтального переполнения на десктопе и ширинах 390/768/1024 px; пароль и повтор, блокировка несовпадения; глазок; каскадные фильтры и сброс зависимых полей; сортировка цен с договорными условиями в конце; английская навигация и `lang`; недопустимое имя; сохранение вузовской принадлежности и новой стоимости без подмены `hourly_rate`; отсутствие runtime-ошибок. Основные экраны дополнительно просмотрены по скриншотам.

Ответы API подменяются локальными тестовыми данными. Это подтверждает работу интерфейса и сформированные запросы, но не успешность реальной регистрации или загрузки в production.

Дополнительно браузером проверены карточки рекомендаций и объяснения, переходы к проекту/профилю/обращению, фильтр проекта, скрытие/возврат, мобильная ширина 390 px, английские подписи, ошибка загрузки с очисткой устаревших карточек и повторной попыткой, сохранение отдельных настроек без сброса прежних, переход из уведомления с отметкой прочтения. Новые экраны просмотрены по скриншотам. Realtime в mock-тесте не подключается к живому Supabase и не считается проверенным.

Повторить:

```bash
npm ci
npm run test:db
npm run test:recommendations
npm run typecheck
npm run lint
npx playwright install chromium
npm run test:ui
```

`test:ui` сам выполняет тестовую сборку и запускает локальный сервер на порту 3001. При необходимости путь к заранее установленному Chromium задаётся `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`. Отчёт и скриншоты пишутся в `test-results/ui` и не коммитятся. После теста для выпуска **обязательно заново собрать приложение с production-переменными**.

## Что ещё не подтверждено

- Авторизация, доставка писем, PostgREST, Storage, Edge Function и Realtime-оповещения рекомендаций в целевом Supabase после миграций.
- Применимость схемы размещения для персональных данных, утверждённые согласия и тексты юриста.
- DNS/HTTPS nearbyexperts.ru, основной production-адрес и настроенный SMTP.
- Оплата, эскроу, выплаты, возвраты и webhooks партнёра: интеграция не реализована без его API.
- Полный перевод рабочих разделов: английский пока beta.
- Работа всего прежнего аукционного/файлового функционала на реальном staging после обновления зависимостей; выполнить прежний staging-план отдельно. Старый seed создаёт отзывы к незавершённому проекту через service role: теперь они закономерно скрыты до завершения; не считать это ошибкой миграции.
