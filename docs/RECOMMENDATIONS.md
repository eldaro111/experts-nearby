# Рекомендации проектов и специалистов

Обновление от 4 октября 2026. Добавляется поверх правок пилота в ветке `codex/pilot-feedback-2026-10`. Код и миграция подготовлены; к рабочему Supabase они этим запуском не применялись.

## Что получает пользователь

- Раздел `/recommendations` в рабочей навигации: «Проекты для меня» и «Специалисты для проектов».
- Исполнитель видит открытые проекты, подходящие его навыкам и специализациям. Автор проекта видит подходящих специалистов и может перейти в профиль или предложить сотрудничество через существующее вступительное обращение.
- В карточке объясняется совпадение: конкретные навыки, специализации, общий вуз. Это помощь в знакомстве, а не подтверждение квалификации или гарантия выполнения заказа.
- Новый подходящий вариант появляется в колокольчике и центре уведомлений. Запись создаётся на сервере, даже если получатель сейчас не открыл сайт; при следующем входе он увидит её. Для открытого сайта используется существующая подписка Supabase Realtime.
- Каждый тип оповещений отдельно отключается в `/settings#notifications`. Подборка остаётся доступной вручную. Неподходящую карточку можно скрыть, а затем вернуть скрытые рекомендации.

Это **уведомления внутри сайта**. Email, Telegram, SMS и браузерные push-уведомления в данное обновление не входят.

## Как работает подбор

Теги навыков и специализаций сравниваются без учёта регистра, лишних пробелов и различия «е/ё». Значимые символы сохраняются: `C`, `C++` и `C#` не считаются одним навыком. Учитываются первые 100 тегов длиной до 100 символов. Семантического поиска, словаря синонимов и внешней ИИ-модели нет.

Внутренний балл: до 70 за долю совпавших требуемых навыков, 25 за совпадение хотя бы одной специализации, 5 за общий вуз. Порог — 25. Один общий вуз без совпадений навыков или специализации недостаточен. Балл используется для сортировки и не показывается как вероятность успеха.

Исключаются собственные, приватные, завершённые проекты и проекты с прошедшим сроком; скрытые профили; исполнители с доступностью 0; пары с существующим откликом или приглашением, включая отклонённые. Неуказанная доступность допускается. Профили с видимостью «Только пользователям платформы» доступны в подборке авторизованному автору проекта. Скрытая цена не раскрывается. Стоимость не участвует в подборе: сопоставимого структурированного бюджета проекта в текущей модели нет.

Подборки и оповещения охватывают проекты из каталога `listings`. Аукционы и отдельные задачи внутри закрытой рабочей зоны не рекомендуются.

## Оповещения и ограничения пилота

- Не более **трёх оповещений за скользящие 24 часа** суммарно по обеим категориям одному пользователю.
- Одна пара «проект–специалист» оповещает каждого получателя только один раз. Редактирование проекта, скрытие/возврат карточки и прочтение уведомления не создают повторов.
- Новые настройки включены по умолчанию; существующие пользовательские настройки остальных событий сохраняются.
- Изменение значимых полей профиля или проекта запускает подбор в серверной транзакции. Отложенные триггеры учитывают приглашение, созданное в той же транзакции.
- При входе и открытии подборки выполняется обновление текущего пользователя, ограниченное сервером до одного раза за 5 минут. Кнопка «Обновить подборку» всегда перечитывает актуальную выдачу, но не обходит этот лимит пересчёта.
- При пересчёте источника сохраняются до 50 лучших пар; в выдаче — до 50 карточек. Начальное заполнение при входе обрабатывает профиль пользователя и до 20 его последних открытых публичных проектов. Фильтр в интерфейсе также содержит эти 20 проектов.
- Если суточная квота исчерпана или получатель занят другой транзакцией, новые оповещения могут быть отправлены при следующем значимом изменении либо следующем обновлении при входе. Отдельного ежедневного фонового задания нет. На большом каталоге следует перейти к индексированному подбору и очереди, предварительно измерив нагрузку.

## Доступ и приватность

Служебные таблицы пар, журнала доставки и времени обновления недоступны браузеру. Через RPC пользователь получает только свои рекомендации. Скрытие карточки действует только на свою сторону: выбор автора не скрывает проект у исполнителя.

При каждом чтении и доставке заново проверяются актуальные права и условия подбора. Старые карточки не показывают профиль после его скрытия или проект после закрытия. Текст уведомления общий, без сохранённых имён, названий проектов и навыков; ссылка открывает заново проверенную подборку. Служебные идентификаторы остаются в payload. Журнал отправки не сбрасывается при удалении проекта или изменении даты записи в пользовательском inbox. При удалении аккаунта получателя его журнал удаляется каскадно.

## Подключение

1. На отдельном тестовом Supabase проверить исходную схему и применить миграции по порядку. Если пилот уже установлен, нужна только новая `supabase/migrations/20261004150000_recommendations.sql`. Она должна идти **после** `20261004090000_pilot_feedback.sql`; повторно вручную её не выполнять.
2. Для свежей базы нужны также обе исходные миграции 20260823. Для существующей базы baseline повторно не применять. Общий порядок — в [DEPLOY_NEARBYEXPERTS.md](DEPLOY_NEARBYEXPERTS.md).
3. Выполнить `npm ci`, `npm run test:db`, `npm run test:recommendations`, `npm run typecheck`, `npm run lint` и `npm run test:ui` с установленным Chromium.
4. Собрать и выпустить приложение с **настоящими** переменными целевого Supabase после миграции. Тестовая браузерная сборка использует фиктивные публичные ключи и не подходит для production.
5. На staging войти под двумя разными пользователями: заполнить одному навыки, второму опубликовать соответствующий проект. Проверить обе подборки, получение уведомления при закрытом сайте и после входа, живое обновление колокольчика, выключение каждой категории, скрытие/возврат, приватность, отклик и завершение проекта. Повторное сохранение не должно создавать дубликаты.

Новые ключи сторонних сервисов, SMTP, Edge Function или cron для этой функции не нужны. Она использует текущие Auth/PostgreSQL/RPC/Realtime Supabase. Реальные JWT, PostgREST и Realtime необходимо проверить на целевом staging: локальные тесты проверяют SQL и интерфейс раздельно.
