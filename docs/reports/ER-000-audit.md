## 4. Подтверждённые проблемы и отдельные предположения

### F-01. Недоверенная запись в историю — высокая важность

Доказательства: `supabase/migrations/20260823110236_baseline_public.sql:721–797` и `:4669–4671`. `append_project_activity_internal` — security-definer функция; EXECUTE явно выдан `anon` и `authenticated`. Она проверяет членство только при ненулевом `auth.uid()`, принимает тип/title/entity/metadata от вызывающего и не требует существования указанной сущности. Прямой INSERT в таблицу для обычного пользователя закрыт, но это не закрывает путь через RPC.

**Воспроизведено на всех шести локальных миграциях в PGlite, код 0:**

| Проверка | Наблюдение |
| --- | --- |
| Прямой INSERT authenticated | Запрещён, как и ожидается |
| Вызов функции автором проекта | Создано вымышленное `task_completed` с несуществующим entity_id |
| Вызов посторонним authenticated | Отклонён проверкой членства |
| Вызов anon без JWT claim | Создано вымышленное событие в существующем приватном проекте, actor_id = NULL |

Это дефект локальной схемы и блокирующее основание для доверия к будущим расчётам ER-005. Удалённый HTTP RPC и фактические live GRANT/gateway не проверялись; успешная эксплуатация production не утверждается. Нужна отдельная задача на проверку и исправление вызываемости, происхождения событий и регрессию. Исправление в ER-000 не выполнялось.

`src/lib/projectActivity.ts` является no-op shim: не пишет переданный клиентом event и возвращает `skipped:true`. Его комментарий о серверном происхождении не устраняет доступную SQL-функцию. Нельзя считать этот файл действующим защищённым интерфейсом записи.

### F-02. История неполна для периодной аналитики

- `trusted_activity_from_task` (baseline:3760–3871) пишет создание/удаление, статус и исполнителя. **Изменение только `due_at` проверено в памяти: число событий не меняется.** Клиент отправляет уведомление о переносе, но отдельной неизменяемой версии согласованного плана это не создаёт.
- `project_documents` хранит актуальный content и updated_at; UI допускает правку/удаление. Версии документов и activity-триггер документов не найдены. `project_events` хранит встречи/события без подтверждения состоявшейся консультации и журнала изменений.
- `contributions` содержит часы и подтверждение автора проекта; часы заявлены пользователем. Триггер фиксирует добавление/первое подтверждение, но это не полный цикл замечаний, доработок, рассмотренных гипотез и исправлений истории.
- `task_completed` можно получить при последовательных сменах статуса; квалифицирующие результаты требуют дедупликации и правил приёмки. Техническое событие не равно принятому научному результату.
- События имеют ID/project/actor/type/entity/metadata/серверный created_at; нет отдельной формализованной модели источника, claimed/recorded date, импорта, исправления с причиной и версии методики.
- `project_activity.project_id` удаляется каскадно с проектом (baseline:3983–3984); actor_id при удалении профиля становится NULL (5077–5078). Это не вечный архив. Сроки хранения и доступ нужно определить отдельно.
- `ProjectActivity.tsx:70–75` берёт последние **80** событий без отчётной пагинации/периода; это экран истории, не выборка всех оснований для расчётов.

### F-03. Семантика часового пояса не соответствует интерфейсу

`listings/page.tsx:262` предлагает пример `UTC+3`, но новые формы сохраняют IANA (`Europe/Moscow` и т. п.). Фильтр `includes` сравнивает строки, а не часовые зоны: такой ввод не найдёт соответствующий IANA-проект. Пустое значение при активном фильтре не проходит, но канонизация алиасов и согласованная семантика отсутствуют. Это подтверждено статически, браузерный сценарий не запускался.

`TimezoneSelect` пригоден для развития: обычный select, российские и зарубежные зоны, сохранение неизвестного прежнего значения. Его следует расширить, а не создавать конкурирующий компонент. Нет полнотекстового поиска, текущего UTC-сдвига/обработки DST на дату; список ограничен. Нельзя выводить город из legacy offset. Фильтр нужно называть «Часовой пояс проекта»; совместимость расписаний относится к ER-004.

### F-04. Ограничения выдачи и обслуживания

`listings/page.tsx:64–67` и `UniversityDirectory.tsx:73–86` загружают набор строк и фильтруют в браузере; явного серверного разбиения выдачи здесь нет. Это установленное свойство кода. **Потеря части live-выдачи, конкретный лимит и медленная работа при нагрузке — пока предположения**, которые требуют фактических настроек и измерений. `search_startups` уже использует серверную пагинацию; её наличие не распространяется на остальные каталоги.

Нет репозиторного CI workflow и воспроизводимой self-hosted конфигурации. ESLint выдаёт 26 предупреждений (any, неиспользуемые значения, эффекты, экспорт PostCSS), но ошибок нет. Это отдельные будущие работы, не основание обновлять зависимости в аудите.

### Не подтверждено и не объявляется дефектом

Регион/тариф/версии облака, drift live-схемы, небезопасность конкретного production endpoint, поломка писем, потеря файлов, отсутствие backup, предел производительности, величина экономии сжатия, соответствие законодательству и текущие цены. Для каждого нужны отдельные сведения/проверки. Исторические результаты владельца и `docs/VALIDATION.md` не опровергаются, но не заменяют текущую проверку.

## 5. ER-005 — критериальный анализ студента и научного руководителя

**Реализовано:** задачи и сроки/исполнитель/статусы, вклад и подтверждение, файлы с task_id/меткой версии, редактируемые документы, календарные события, история, членство проекта, общие отзывы после завершения. Источники: `src/components/project/types.ts`, `ProjectTasks`, `ProjectContributions`, `ProjectFiles`, `ProjectDocuments`, `ProjectCalendar`, `ProjectCompletion`, SQL baseline/pilot.

**Заготовки и ограничения:** project_activity — основа после исправления F-01 и решения F-02; `academic_role` — только атрибут профиля. Роль teacher/representative и принадлежность к вузу не означают назначенного руководителя или право читать закрытые проекты вуза. Отдельной аналитической заготовки с методикой не найдено.

**Только требования:** одинаковые данные + версия методики должны давать одинаковый результат без LLM; показатели регулярности, принятого плана, ответа на замечания, рассмотренной инициативы, консультаций/проверок руководителя, концентрации результатов к сроку, полноты наблюдения. ## 6. ER-011 — платный ИИ-планировщик YandexGPT

**Отсутствует:** серверная интеграция модели, структурированные черновики, хранение версии исходных данных, граф зависимостей/этапов, безопасное применение и дедупликация предложений, платная подписка, атомарный резерв/сверка денежных расходов, общий выключатель и тесты модели/бюджета.

Предусмотреть в отдельной реализации:

1. В закрытой зоне проекта пользователь задаёт цель/ограничения, получает предлагаемые этапы/задачи, сводку/перепланирование, повестку встречи и напоминания. При нехватке данных помощник уточняет; длительности маркируются как оценки. Выполнение кода и произвольные внешние действия в MVP не входят.
2. Сервер проверяет пользователя, фактические права проекта и подписку; ограничивает разрешённый контекст. Модель не получает административные ключи, прямой доступ к БД, чужие проекты и все файлы/переписку автоматически.
3. **До платного вызова** атомарно резервирует консервативный максимум расхода. Ограничивает размер входа/выхода, число вызовов на действие, частоту, параллельность, повторы, квоты пользователя/проекта/плательщика и общий бюджет периода; предусмотрен выключатель.
4. Валидирует структуру/ID/даты/циклы, сохраняет черновик, показывает пользователю. Применяет только после подтверждения и повторной проверки прав/актуальности задач, идемпотентно, через существующие разрешённые операции с сохранением SQL-ограничений.
5. Сверяет использование по версии модели/тарифа и request ID, не пишет закрытый контекст/секреты в обычные логи. Неизвестный исход таймаута не должен приводить к бесконечным повторным вызовам или слепому освобождению резерва.
6. Сначала тестируется с фиктивным провайдером. Публичный платный запуск зависит от серверных подписок/квот ER-010. Правила командного плательщика ещё не утверждены; точные модель/API/тариф и provider budget controls ещё требуют исследования.

Отключение YandexGPT/подписки не должно ломать обычные задачи и календарь, удалять историю или отключать базовые расчёты ER-005. Созданный моделью план не считается выполненным результатом студента. API не вызывался; цены, суммы и гарантированный лимит всех списаний общего аккаунта не утверждались.

## 9. Повторение локальной проверки истории

Этот JavaScript запускается **только в Node с PGlite в памяти из корня проекта** (`node --input-type=module -`, передача через stdin). Он не подключается к Supabase и не записывает файлы. Это не SQL для панели рабочей БД. Установленные зависимости уже использованы; установка/миграция в облако не требуется.

```js
import { PGlite } from '@electric-sql/pglite';
import { readFileSync, readdirSync } from 'node:fs';
import assert from 'node:assert/strict';
const db = new PGlite();
try {
  await db.exec(`create publication supabase_realtime;
    create role anon; create role authenticated; create role service_role bypassrls;
    create schema auth; create schema storage;
    create table auth.users(id uuid primary key,email text);
    create function auth.uid() returns uuid language sql stable as $$
      select nullif(current_setting('request.jwt.claim.sub',true),'')::uuid $$;
    create table storage.buckets(id text primary key,name text,public boolean,
      file_size_limit bigint,allowed_mime_types text[]);
    create table storage.objects(id uuid primary key default gen_random_uuid(),
      bucket_id text references storage.buckets(id),name text,owner_id text,
      metadata jsonb,created_at timestamptz default now());
    alter table storage.objects enable row level security;
    grant usage on schema public,auth,storage to anon,authenticated,service_role;
    grant select,insert,update,delete on storage.objects
      to anon,authenticated,service_role;`);
  for (const name of readdirSync('supabase/migrations')
      .filter(x => /^\d+.*\.sql$/.test(x)).sort()) {
    const sql = readFileSync('supabase/migrations/' + name, 'utf8');
    await db.exec(name.includes('baseline') ? 'begin;\n' + sql + '\ncommit;' : sql);
  }
  const owner = '00000000-0000-4000-8000-000000000001';
  const outsider = '00000000-0000-4000-8000-000000000002';
  await db.query('insert into auth.users(id) values ($1),($2)', [owner, outsider]);
  await db.query(`insert into profiles(user_id,display_name)
    values ($1,'Audit Owner'),($2,'Audit Outsider')`, [owner, outsider]);
  const project = (await db.query(`insert into listings
    (user_id,created_by,title,visibility) values ($1,$1,'Audit private project','private')
    returning id`, [owner])).rows[0].id;
  const task = (await db.query(`insert into tasks(project_id,title)
    values ($1,'Audit task') returning id`, [project])).rows[0].id;
  const setUser = async (id, role) => {
    await db.exec('reset role');
    await db.query("select set_config('request.jwt.claim.sub',$1,false)", [id || '']);
    await db.exec('set role ' + role);
  };
  const append = `select public.append_project_activity_internal(
    $1,'task_completed','Synthetic audit event',null,'task',$2,'{}'::jsonb) as id`;
  const missingEntity = '00000000-0000-4000-8000-000000000099';
  await setUser(owner, 'authenticated');
  await assert.rejects(db.query(`insert into project_activity(project_id,type,title)
    values ($1,'task_completed','Direct insert')`, [project]), /permission denied/);
  assert.ok((await db.query(append, [project, missingEntity])).rows[0].id);
  await setUser(outsider, 'authenticated');
  await assert.rejects(db.query(append, [project, missingEntity]));
  await setUser(null, 'anon');
  const anonymous = (await db.query(append, [project, missingEntity])).rows[0];
  assert.ok(anonymous.id);
  await setUser(null, 'postgres');
  assert.equal((await db.query('select actor_id from project_activity where id=$1',
    [anonymous.id])).rows[0].actor_id, null);
  await setUser(owner, 'authenticated');
  const count = async () => Number((await db.query(
    'select count(*) as n from project_activity where project_id=$1', [project]
  )).rows[0].n);
  const before = await count();
  await db.query("update tasks set due_at='2027-01-01T00:00:00Z' where id=$1", [task]);
  assert.equal(await count(), before);
  console.log('Confirmed F-01/F-02 in memory; no remote connections or file writes');
} finally { await db.close(); }
```
