## 2. Включение рекламного предпросмотра

Флаг читается **при сборке** (переменная `NEXT_PUBLIC_*` встраивается в клиентский код):

```powershell
# локальная демонстрация
$env:NEXT_PUBLIC_AD_SLOTS = 'demo'; npm run dev
# или сборка для предпросмотра
$env:NEXT_PUBLIC_AD_SLOTS = 'demo'; npm run build; npm start
```

Без переменной или с любым значением, кроме `demo`, мест нет: никакой пустой полосы. В production переменную **не задавать**, тогда пустых баннеров у пользователей не будет. Если заглушки не видны при `demo`:
1. сначала проверить, что сборка сделана с этой переменной;
2. затем — открыть страницу в профиле браузера без расширений и в обычном профиле.

Классы `ad-slot` и подпись не переименовывались ради обхода блокировщиков.

## 4. Ограничения и неизвестное

- **Возврат после входа** работает для входа по паролю. При регистрации, входе по ссылке из письма и онбординге параметр `next` не передаётся: письмо ведёт на `/auth/callback`, и это поведение я не менял, потому что Auth не трогается.
- **Текущий проект** главной хранится только в этом браузере (`localStorage`, ключ на пользователя). Это удобство, а не право доступа: значение сверяется с загруженным списком, недоступный проект забывается. На другом устройстве выбор будет спрошен снова.
- В окне выбора не больше 50 своих проектов и 50 участий.
- Окно задачи только для чтения: статус, сроки и исполнитель меняются в карточке на доске — одно место правок и проверок конфликтов.
- **Приглашённые на события** не показываются: в `project_events` нет участников. Контракт таблицы участников — в пакете Б.
- Гант на касании проверен только кодом (Pointer Events те же, что для мыши); браузерной проверки касания полосы нет. Касание доски и календаря проверено эмуляцией Chromium.
- Safari, Firefox, реальные телефоны и экранные дикторы не проверялись.
- **Сборка на этой машине.** Во время работы свободный лимит памяти Windows был около 2–2,5 ГБ из 49: WSL около 15 ГБ, игра, Discord. Next по умолчанию запускает до 19 рабочих процессов. Около 30 сборок упали с кодами 134, 0xC0000409 и 0xC00000FD («Committing semi space failed»). Это нехватка памяти машины, а не ошибка кода: отдельные повторные сборки того же кода проходили.

  Для финальных прогонов я **временно** добавил в `next.config.ts` строку `experimental: { cpus: 2 }` и собрал два варианта (`demo` и обычный). Затем файл восстановлен побайтно: SHA-256 `5cda67f7…` совпадает с исходным, `git status` по нему чистый. В коммит изменение не входит. На поведение приложения число рабочих процессов сборки не влияет.

  Наборы запускались на этих сборках с флагами повторного использования, добавленными в тесты: `PILOT_UI_SKIP_BUILD`, `INTERFACE_ONLY_ADS`, `INTERFACE_SKIP_BUILD` для обеих фаз, `NAV_UI_SKIP_BUILD`, `MOTION_SKIP_BUILD`. Сами проверки от этого не меняются. `NEXT_PUBLIC_SITE_URL` в сборке влияет только на `metadataBase`.

  Полный `npm run check` (со сборкой из 19 процессов) на этой машине сейчас не проходит по памяти; типы и линтер запускались отдельно.
