# Изоляция выбора проектов между сессиями

14 ноября 2026. Основа исправления — финальный пакет Claude `c63259620c27aed2c58c75c67f14b043aebc0dd6`. Работа выполнена в отдельном worktree `experts-nearby-integration`, ветка `fix/workspace-session-isolation`; соседние worktree не изменялись.

## Причина и исправление

В финальном пакете остался дефект из ревью `ede5041`: `WorkspacePanel` сбрасывал лишь часть состояния при выходе, не сбрасывал его при прямой смене пользователя и принимал завершение старого `loadOverview`. Ожидающий ярлык также мог выполнить переход после смены аккаунта. Секции защищались только от предыдущего запроса той же секции, без привязки к сессии.

Панель разделена на наблюдение за Auth и экземпляр состояния конкретной сессии. При смене личности (включая A → выход → A) синхронно меняется поколение сессии; ключ React сбрасывает списки, выбранный проект, диалог, поиск, ошибки и загрузку вместе. Асинхронные операции проверяют поколение до работы и после ожидания, прежде чем менять состояние, localStorage или маршрут. Поздний первоначальный `getSession` не заменяет уже полученное Auth-событие. Обновление токена того же пользователя не сбрасывает открытый диалог.

Схема авторизации, API и SQL не изменены. Выбранный UUID хранится отдельно для пользователя и проверяется `loadAccessibleProject` по владельцу/действующему участию. Клиентское состояние не предоставляет прав: RLS основной базы остаётся обязательным независимо от результата этого теста.

## Проверки

`scripts/tests/workspace-session-ui.mjs` использует настоящий компонент в браузере, синтетические записи, контролируемые задержки HTTP-ответов и Auth-уведомления через канал установленного Supabase SDK. Это **мок Auth, не реальная смена аккаунта в Supabase**. Внешние HTTP/WS заблокированы. В режиме разработки допускается только локальный HMR Next, без которого эта версия Next не начинает гидратацию.

- На исходном `WorkspacePanel` из `c632596` первый сценарий воспроизвёл дефект: Б уже загрузился, затем пришёл ответ А и нарушил панель/ожидающий переход. Проверка сохранения выбранного проекта Б упала. Результат сохранён в игнорируемом `test-results/workspace-session/baseline-failure.json`.
- После исправления `SESSION_DEV=1 node scripts/tests/workspace-session-ui.mjs`: **8 PASS**. Покрыты поздний первоначальный ответ А после Б и ожидающий ярлык; открытый диалог/выбранный проект при прямом переключении; чужой UUID в сохранённом выборе Б; поздний успешный и ошибочный поиск А; поздняя следующая страница А; выход и повторный вход в А; отсутствие runtime-ошибок. Проверены списки, выбранный проект, поиск, ошибки, состояние загрузки и отсутствие старого перехода. Для обновления токена сохранение диалога проверено отдельно внутри сценария.
- `node node_modules/typescript/bin/tsc --noEmit`: PASS.
- ESLint изменённого компонента и нового браузерного теста: 0 ошибок и предупреждений.

Первый диагностический запуск завис в ожидании запроса, потому что общий стенд блокировал локальный HMR. Его собственное дерево процессов остановлено адресно; затем добавлены таймаут ожидания и локальное исключение HMR. Повтор с таймаутом подтвердил отсутствие запросов при заблокированном HMR. Эти два запуска не считаются проверкой дефекта. Успешный прогон выполнялся после устранения причины. Next dev автоматически дописал служебный блок AGENTS в новом worktree; он удалён с восстановлением исходного содержимого, для тестов генерация отключена временно. Исходный AGENTS сохранён.
