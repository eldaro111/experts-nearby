## Что сделано

Изменены только компоненты чата и их локальный CSS-модуль `ProjectChat.module.css`. Протокол прежний: те же чтения, вставки и обновления, те же поля, прежние права. Изменения в протоколе две:
- вставка передаёт `id`, сгенерированный клиентом;
- запись возвращает строку (`.select('*')`), чтобы обновить сообщение на месте.

1. **Появление сообщений.** Новое сообщение плавно проявляется с подъёмом на 6 px за 200 мс, один раз. Загруженная история не анимируется — ни при открытии, ни при перерисовке, ни при повторном открытии чата. Подтверждённое сервером сообщение сохраняет свой элемент (тот же ключ), поэтому анимация не повторяется и ничего не мерцает.
2. **Прокрутка:**
   - если человек внизу, новое сообщение остаётся в поле зрения;
   - если он читает выше, чат его не сдвигает, а появляется кнопка «Новые сообщения (N)», которая ведёт к первому новому;
   - добавлена кнопка «Показать предыдущие сообщения»: читаемое сообщение остаётся на месте (ручная привязка, `overflow-anchor: none`);
   - при изменении размеров содержимого и панели (`ResizeObserver`) и при мобильной клавиатуре (`visualViewport`, высота панели по видимой области) чат держит низ, только если человек был внизу.
3. **Отправка.**
   - Пузырь показывает «Отправляется…», а отправленным считается только после подтверждения сервера.
   - Дубли исключены:
     - `id` сообщения выбирает клиент, повтор с тем же `id` сервер отклоняет кодом `23505` (проверено в PGlite), и сообщение находится по этому `id`;
     - список сливается по `id`;
     - повторное нажатие и повторный Enter не отправляют второй раз.
   - При ошибке текст остаётся в пузыре «Не отправлено» с причиной. Действия: «Повторить отправку», «Изменить текст» (вернуть в поле), «Удалить черновик» — повтор только по нажатию.
   - Если ответ сервера потерян, чат проверяет сообщение по `id` и сам не отправляет повторно.
   - Enter отправляет, Shift+Enter переносит строку, Enter во время ввода через IME не отправляет.
4. **Действия с сообщением.**
   - Ответ, редактирование, удаление для всех и удаление для себя видны всегда, а не только при наведении, и доступны с клавиатуры. На телефоне цели касания не меньше 44 px.
   - Цитата ответа ведёт к исходному сообщению.
   - Escape отменяет ответ или правку, не закрывая панель; следующий Escape закрывает панель и возвращает фокус на кнопку «Чат команды».
   - Ctrl/⌘+Enter сохраняет правку.
   - Журнал сообщений можно прокручивать с клавиатуры (`role="log"`, фокусируемый).
5. **Оформление.**
   - Сине-белая палитра платформы.
   - Длинные слова и ссылки переносятся внутри пузыря.
   - Аккуратные состояния наведения и фокуса; адаптация к 360 px.
   - При `prefers-reduced-motion` анимаций и плавной прокрутки нет.
   - Индикаторов «печатает», «прочитано», «онлайн» нет: сервер таких данных не даёт.
6. **Смена аккаунта или проекта.**
   - Чат пересоздаётся по ключу «проект : аккаунт», а ответы прежнего поколения отбрасываются.
   - При входе под другим аккаунтом в соседней вкладке сообщения прежней сессии скрываются, поле ввода блокируется, предлагается обновить страницу.
7. **Новые сообщения других участников.** Realtime для `project_messages` на сервере нет (раздел «Серверные замечания»), поэтому чат перечитывает последнюю страницу:
   - при открытии;
   - при возврате фокуса или видимости вкладки;
   - каждые 30 секунд, пока чат открыт.
   Мгновенной доставки нет, и интерфейс её не изображает.

## Серверные замечания (не исправлялись и не маскировались)

Подтверждено в PGlite на настоящей базовой схеме (`scripts/tests/project-chat-db.mjs`):

1. **`project_messages` не входит в публикацию `supabase_realtime`** — там только `notifications`. Мгновенная доставка сообщений других участников невозможна без серверного решения: включить таблицу в публикацию с учётом RLS.
2. **`created_at` при вставке задаёт клиент**, если передаст поле: сервер принимает и прошедшую дату (сообщение «задним числом»). Триггер запрещает менять `created_at` только при обновлении. Чат это поле не передаёт.
3. **`edited_at` при правке обязателен, но значение задаёт клиент:**
   - сервер принимает любое время;
   - повторная правка может сохранить прежнюю отметку.
   Чат всегда ставит текущее время.

Предложение для Codex: серверные `created_at`/`edited_at` (значение по умолчанию и триггер) и решение по Realtime. Это изменения SQL, в этой работе не выполнялись.

Ход прогонов — без сокрытия неудач:
- **Сборки.** Их было три, все прошли с первой попытки; ошибок памяти не было. Тяжёлые прогоны не совпадали с проверками Codex:
  - перед каждым прогоном проверялись процессы;
  - когда Codex запустил свою сборку, а затем `planning-ui`, мой прогон ждал их окончания.
  - Первая проверка ожидания была собрана неверно и ложно показала «свободно»; это замечено, и прогон начат только после прямой проверки.
- **Найдены и исправлены два дефекта интерфейса:**
  - Escape при активном ответе закрывал всю панель. Корень React в App Router — `document`, поэтому `stopPropagation` не помогал; теперь панель пропускает Escape, уже обработанный чатом.
  - Если сервер отклонял сообщение во время плавной прокрутки вниз, пузырь с ошибкой оставался частично ниже видимой области: промежуточные события прокрутки сбрасывали признак «внизу». Теперь программная прокрутка его не сбрасывает, прерывает её только действие человека. Проверка добавлена.
- **Ошибки самого теста** исправлены, бизнес-утверждения не ослаблены:
  - замер шёл до окончания плавной прокрутки;
  - обработчик маршрута снимал себя до `abort` (процесс упал без очистки; после этого своих процессов не осталось, порт 3008 свободен);
  - синтетическое событие клавиатуры не может задать `keyCode`, поэтому ветка IME через `keyCode 229` проверяется модульным тестом.
- **Серверное наблюдение уточнено фактом.** Сначала предполагалось, что правку без `edited_at` сервер пропускает. Проверка в PGlite это опровергла: отметка обязательна, но её значение задаёт клиент. В отчёте — проверенная формулировка.
- **Не повторялись:**
  - `interface-ui` и `pilot-ui` — чат в них не участвует, страницу проекта меняет только плавающая панель чата;
  - `return-ui` и `planning-ui` — новые фильтры стенда включаются только в строгом режиме, а их страницы такими фильтрами не пользуются (проверено поиском);
  - `motion-ui` после последней правки — она касается только прокрутки внутри чата.
- Тестовых серверов и браузеров не осталось.

## Ограничения

- **Мгновенной доставки нет.** Сообщения других участников приходят с задержкой до 30 секунд или при возврате к вкладке (раздел «Серверные замечания», пункт 1).
- **Мобильная клавиатура** обработана через `visualViewport` и наблюдатель размеров. На реальных телефонах не проверялась: эмуляция Playwright не показывает экранную клавиатуру.
- **Ввод через IME** проверен синтетическими событиями `composition*` и модульным тестом. Реальные методы ввода — при ручной приёмке.
- **Удаление** по-прежнему подтверждается окном браузера `confirm`; прежнее поведение сохранено.
- **Ссылки** в тексте остаются текстом: длинные переносятся, кликабельными не стали — новые возможности не добавлялись.
- **Язык.** Подписи чата, как и раньше, только на русском; общий словарь переводов не трогался, чтобы не конфликтовать с интеграцией Codex.
- **Ответы, которые сейчас не загружены.** Цитата сообщения, которое было старше загруженной страницы, показывается только после «Показать предыдущие сообщения»; так было и раньше.

## Ручная приёмка

1. Открыть «Чат команды». История появляется без анимации и прокручена вниз; закрыть и открыть — анимация не повторяется.
2. Со второго аккаунта отправить сообщение. В первой вкладке, находясь внизу, вернуть фокус окну — сообщение плавно появляется и видно.
3. Прокрутить вверх, отправить ещё одно со второго аккаунта — позиция не меняется, появляется «Новые сообщения (1)», кнопка ведёт к нему.
4. «Показать предыдущие сообщения» (если их больше 50) — читаемое сообщение остаётся на месте.
5. Набрать текст с Shift+Enter, отправить Enter — «Отправляется…», затем обычное сообщение. Двойной Enter даёт одно сообщение.
6. Отключить сеть и отправить — «Не отправлено», текст сохранён. Включить сеть, «Повторить отправку» — одно сообщение.
7. Ответить, отредактировать, удалить с клавиатуры. Escape отменяет ответ, второй Escape закрывает панель.
8. Телефон: действия видны без наведения, поле ввода не закрыто клавиатурой.
9. Системная настройка «уменьшить движение» — без анимаций.
