# Правила работы с «Эксперты Рядом»

Это существующий работающий продукт. Развивать его небольшими согласованными задачами, не создавать заново.

- Перед работой читать применимые AGENTS.md, `EXPERTS_ROADMAP_CODEX.md`, `docs/PROJECT_STATE.md` и задание; проверять ветку, SHA и Git status. Сохранять чужие локальные изменения, UUID, связи, маршруты, миграции и действующие ограничения доступа.
- Не читать и не выводить значения `.env.local`, других файлов с секретами, ключи, пароли и дампы. Для структуры настроек использовать `.env.example`; наличие секретов проверять без вывода значений.
- До запуска читать скрипты. `localhost` не означает локальную БД. `seed:staging` и `staging:check` создают данные; название среды не подтверждает безопасность назначения.
- Для аудита использовать статические проверки и изолированные тесты в памяти. Не считать PGlite, моки или сборку проверкой реальных Auth, Storage, Realtime и production.
- ER-000 разрешает менять только этот файл, `docs/PROJECT_STATE.md`, `docs/ROADMAP.md`, `docs/INFRA_INVENTORY.md`, `docs/reports/ER-000-audit.md`. Исходную дорожную карту сохранить. По завершении ER-000 остановиться.
- Для ER-000 запрещены изменения рабочего кода, зависимостей, SQL, облачных данных, Vercel и DNS; commit, push, merge и deploy не входят в задание. Следующая задача требует отдельного поручения.
- Сохранять поддержку обычных файлов и `nearby-pack-v1`, декодер, приватные бакеты и права скачивания. Откат интерфейса без декодера несовместим с сохранёнными пакетами.
- При планировании переноса учитывать Next.js, PostgreSQL/RPC/RLS, Auth, Storage, Realtime, Edge Functions, почту, логи и восстановление. Не заменять основную базу старым staging. Сохранять почтовые DNS-записи Яндекс 360.
- ER-005 — воспроизводимый критериальный анализ с графиками без обязательной LLM; ER-011 — отдельный планировщик YandexGPT с подтверждением изменений, серверными правами подписки и лимитами расходов. Не подменять их лентой событий или рекомендациями экспертов.
- В отчётах на русском разделять прочитанное, статически проверенное, фактически запущенное, результаты и неизвестное. Дефекты описывать с доказательствами; исправлять только в разрешённом объёме.
